# 行业常识

## 问：软件行业的项目经理日常工作内容和职责是什么？

答：软件行业的项目经理（Project Manager，PM），核心不是“管人”，而是确保一个软件项目能够在范围、时间、成本、质量和风险约束下顺利交付。

如果你是程序员，可以把项目经理理解成：

负责让“需求 → 开发 → 测试 → 上线 → 验收”这条链路持续往前走的人。

### 一、项目经理每天到底在干什么？

一个比较典型的软件项目，PM 的工作大概是：

```txt
客户 / 产品
    ↓
需求确认
    ↓
项目计划
    ↓
任务拆分
    ↓
开发 ─── 测试 ─── 运维
    ↓        ↓        ↓
    └────────┴────────┘
             ↓
           上线
             ↓
           验收
```

PM 负责协调这条链路。

#### 典型的一天

上午可能：

```txt
09:00  查看项目进度
09:30  开项目例会
10:00  和开发确认昨天的问题
10:30  和测试确认 Bug
11:00  和客户确认需求变更
```

下午：

```txt
14:00  更新项目计划
15:00  和技术负责人讨论延期风险
16:00  跟进第三方接口
17:00  给领导/客户发项目进度
18:00  整理风险和第二天计划
```

所以 PM 的工作有一个非常明显的特点：

大量沟通、协调、跟进、决策和风险处理。

### 二、最核心的 7 项职责

#### 1. 需求管理

首先要搞清楚：

到底要做什么？

比如客户说：

“我要一个用户管理系统。”

PM 不能直接丢给程序员。

需要进一步拆：

```txt
用户注册
用户登录
用户信息修改
角色管理
权限管理
用户查询
批量导入
操作日志
```

然后继续确认：

```txt
哪些必须做？
哪些可以以后做？
什么时候交付？
谁负责？
验收标准是什么？
```

### 三、项目计划

项目经理需要把：

“我要做一个系统”

变成：

“什么时候，谁，做什么。”

例如：

```txt
需求分析       9/1 - 9/5
UI设计         9/3 - 9/8
后端开发       9/8 - 9/20
前端开发       9/8 - 9/22
联调           9/23 - 9/26
测试           9/27 - 10/3
上线           10/6
```

然后拆成具体任务：

```txt
登录 API
RBAC
数据库设计
用户列表
角色管理
前端页面
接口联调
测试用例
部署
```

### 四、进度管理

这是 PM 非常重要的一项工作。

比如计划：

```txt
后端开发
9/8 ~ 9/20
```

到了 9 月 15 日，PM 要知道：

```txt
完成了吗？
还剩多少？
为什么没完成？
会不会影响后面的测试？
需要增加人手吗？
```

尤其要发现：

项目什么时候开始有延期风险。

例如：

```txt
支付接口
     ↓
第三方接口还没提供
     ↓
后端无法开发
     ↓
联调无法开始
     ↓
测试延期
     ↓
上线延期
```

一个好的 PM 会尽早发现这个问题，而不是到了上线当天才说：

“项目延期了。”

### 五、风险管理

这其实是 PM 很核心的一项能力。

例如：

#### 技术风险

```txt
第三方 SDK 不稳定
数据库性能未知
高并发方案还没验证
```

#### 人员风险

```txt
核心开发人员请假
关键人员离职
某个人承担太多模块
```

#### 进度风险

```txt
需求不断增加
测试周期不足
接口迟迟没有提供
```

#### 外部风险

```txt
第三方接口
客户审批
服务器
证书
域名
采购
```

PM 要做的是：

```txt
发现风险
   ↓
评估影响
   ↓
制定解决方案
   ↓
指定负责人
   ↓
持续跟踪
```

### 六、协调开发、测试、产品、客户

软件项目里很容易出现这种情况：

```txt
产品：这个功能必须这周上线

开发：做不完

测试：测试时间不够

运维：服务器还没准备

客户：我还要增加两个需求

老板：项目不能延期
```

PM 就在中间协调。

例如：

当前需求增加了两个模块，如果保持原上线时间，需要减少另外两个非核心功能；否则预计延期一周。

这就是 PM 很重要的能力：

把冲突转换成可讨论的方案。

而不是简单地：

“大家加班做一下。”

### 七、会议和沟通

PM 会参加/组织很多会议。

常见的：

#### 项目启动会

```txt
项目目标
项目范围
人员
时间
里程碑
风险
```

#### 每日站会

```txt
昨天做了什么？
今天做什么？
有没有阻塞？
```

#### 周会

```txt
整体进度
本周完成
下周计划
风险
问题
```

#### 需求评审

```txt
需求是否明确？
技术是否可行？
工作量多少？
上线会议
版本
部署
数据库
回滚方案
监控
负责人
```

### 八、文档也是 PM 的重要工作

常见文档：

```txt
项目计划
需求文档
项目排期
任务清单
会议纪要
项目周报
风险清单
问题清单
变更记录
上线计划
验收报告
```

例如项目周报：

```txt
项目：XXX系统

本周完成：
- 用户模块
- RBAC
- 登录

下周计划：
- 角色管理
- 权限管理
- 联调

当前风险：
- 第三方支付接口尚未提供

项目进度：
75%

预计上线：
10月6日
```

### 九、PM 和程序员最大的区别

这是非常值得理解的一点。

程序员关注：

“这个东西怎么实现？”

PM 更关注：

“这个东西什么时候完成？谁完成？是否符合需求？有什么风险？”

比如：

#### 程序员

```txt
Redis缓存
数据库索引
goroutine
gRPC
MQ
微服务
```

#### PM

```txt
这个功能什么时候完成？
需要几个人？
有没有风险？
测试什么时候开始？
客户什么时候验收？
```

### 十、PM 不一定需要很强的编程能力

但是软件行业 PM 如果懂技术，会非常有帮助。

例如程序员说：

“这个接口依赖第三方 OAuth 服务，目前 OAuth 服务还没有提供测试环境。”

纯业务 PM 可能只能记录：

“接口有问题。”

技术背景的 PM 则能进一步理解：

```txt
OAuth
   ↓
第三方测试环境
   ↓
接口联调
   ↓
登录功能
   ↓
测试
```

因此能够判断：

如果第三方环境周五还不能提供，那么登录模块的联调会影响整个测试阶段。

这就是技术背景带来的优势。

### 十一、技术 PM 和普通 PM

软件公司里其实还有一个非常重要的区别：

|               | 项目经理 | 技术项目经理 |
| ------------- | -------- | ------------ |
| 项目计划      | ✅       | ✅           |
| 需求协调      | ✅       | ✅           |
| 人员协调      | ✅       | ✅           |
| 进度管理      | ✅       | ✅           |
| 风险管理      | ✅       | ✅           |
| 技术方案      | 一般     | 较强         |
| 架构理解      | 一般     | 较强         |
| 技术风险      | 基础     | 较强         |
| Code/技术细节 | 少       | 可能参与     |
| 与架构师沟通  | 需要     | 深度参与     |

如果一个人本身就是程序员，再转项目管理，**技术项目经理（Technical PM）**往往是一个比较自然的方向。

### 十二、但 PM 最大的挑战不是技术

而是：

**沟通**

你会遇到：

```txt
老板
客户
产品
开发
测试
运维
供应商
第三方公司
```

而且这些人的目标经常不同。

例如：

```txt
客户：我要更多功能

产品：必须满足客户

开发：需求太多

测试：没时间测试

老板：不能延期
```

PM 要做的是找到一个大家能够接受的方案。

### 十三、项目经理和产品经理不要混淆

这是软件行业里很容易混淆的两个职位。

**产品经理 Product Manager**

核心问题：

做什么？为什么做？

例如：

```txt
用户需要什么？
功能是什么？
产品怎么设计？
商业目标是什么？
```

**项目经理 Project Manager**

核心问题：

怎么把它按计划做出来？

例如：

```txt
什么时候做？
谁来做？
做到什么程度？
有什么风险？
什么时候上线？
```

简单记：

```txt
产品经理
    ↓
决定「做什么」

项目经理
    ↓
负责「把它做出来」
```

实际公司里两者边界可能会重叠。

### 十四、如果你是程序员，转 PM 要补哪些能力？

如果你已经有多年软件开发经验，那么技术通常不是最大的短板。

需要重点补：

```txt
① 项目计划
② WBS / 任务拆分
③ 进度管理
④ 风险管理
⑤ 需求管理
⑥ 沟通协调
⑦ 会议管理
⑧ 项目文档
⑨ 成本/资源管理
⑩ 敏捷开发
```

尤其建议掌握：

```txt
Scrum
Kanban
Jira
Confluence
Excel
Gantt Chart
WBS
RACI
Risk Register
```

### 最后用一句话概括

软件项目经理不是“负责催程序员的人”。

更准确地说：

**PM 的工作是把目标、需求、人员、时间、资源和风险组织起来，让一个复杂的软件项目能够从“想法”最终变成“可以交付的产品”。**
